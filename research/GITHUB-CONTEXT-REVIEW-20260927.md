## 最适合当前需求的组合

先保留可靠的调度：新任务进入日志 → 按实际路由检查完整请求 → 必要时摘要 → 保存并重建请求 → 继续。可视化只读原日志及官方投影。数据展示不会改变压缩触发时机，也不会增加模型调用。

设置页采用 DSH 原生 SegmentedTabs 分成上下文概览、压缩设置。切换会话只读取该会话投影，不打开/运行 Agent。宿主推送驱动更新；每段会话的历史列表最多 12 条、工具列表最多 8 项。页面不轮询，不携带完整历史原文。压缩配置草稿在两个页签间保留，概览使用已保存值。

本版展示三种独立口径：

1. 上下文占用：官方 contextPressure 的提供方锚定估算；同时显示最近提供方实测输入。容量与读数可能异步，不能用作调度输入。
2. 内容组成：官方 contextBreakdown 的固定密度估算；系统、schema、消息三类，不把占用按比例强行摊平。中文、图片、JSON 都可能有误差。
3. 累计用量：官方 tokenUsage，主请求及重试的累计报告，不是窗口、账单或含摘要的完整成本。

压缩前后只比较被替换片段，使用相同的公开估算方法。compaction/summary 不能单独证明成功，必须检查紧邻替换事件及 compaction/end。崩溃遗留开始事件在 session/end-seed 后标为中断；失败后已替换内容不会误报回滚。用户原日志不新增专属必需事件。

## 后续可独立验证的增强

- 摘要携带原始事件引用，并提供受控的历史检索：解决压缩后细节找回，需要单独验证模型是否能正确使用，不承诺无损。
- 六类内容细分及完整上下文浏览：需要正确处理表面替换、注入、图片和反向 seq 范围，并按展开动作取正文，避免每次推送整个历史。
- 指令/技能重复审计：只读报告后由用户决定精简；不自动改变现有能力。

## 本次验证边界

使用真实 AgentLoop 配合模拟适配器验证先压缩、失败、恢复与回放；严格区分静态检查、离线运行、真实 Web profile 和真实模型。验证记录见 ../verification/RESULTS.md。参考代码仅保存于 research，不执行、不作为生产依赖或打入 tgz。没有安装第三方插件、修改用户日常 profile，也没有把第三方兼容声明当成本插件效果证明。
