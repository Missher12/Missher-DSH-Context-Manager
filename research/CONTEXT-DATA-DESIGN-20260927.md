# 上下文管理：先把数据看清，再控制压缩

本轮目标：提供可直接查看、可交互的 DSH 风格数据界面，明确每个数字从哪里来，再划定正式插件的数据接入范围。用户最新澄清是在“轨迹”后增加同级“上下文”视图，设置里只有参数；此前输入框摘要和侧栏布局是误解，已被取代。

交付状态：`preview/context-inspector/dist/index.html` 是独立、自包含的界面预览。不是新版本安装包，不连接日常 profile。现有 `0.2.1` 包保持原字节和 SHA。

## 问题、原因、影响、推荐方案

**问题：** 0.2.1 更像压缩控制面板，虽然有诊断数据，但用户难以看清模型到底携带了什么、何时增长、一次压缩具体改变了什么。

**原因：** 现有概览只有三类组成、最多 8 个工具定义、12 条请求和压缩记录，展示以文字列表为主；未建立内容索引、按次请求视图和关联交互。

**影响：** 用户只看到一个比例和若干统计，无法从大头追到具体工具输出或技能；也难以解释“为什么 79.9% 就要压缩”。

**推荐方案：** 一个独立 Bundle 内保留压缩执行器与只读观察器两个职责。“对话 / 轨迹 / 上下文”作为同一会话的三个主视图；上下文内包含总览、内容查看器和变化记录，设置页只提供压缩参数。数值、来源、时点可解释，点击能追到具体内容，展示失败不能拖住任务执行。

## 页面与交互

“上下文”位于“轨迹”后，与“对话”和“轨迹”同级。点击后在主内容区显示数据，三个视图互相切换；数据页内的总览、内容查看器、变化记录为二级导航。进入设置后只保留参数表单，返回会话保留已选视图和数据页签；保存参数后更新上下文内的检查结果。预览默认打开上下文以便审阅，轨迹页仅示意既有入口；正式宿主仍沿用自己的默认视图和轨迹实现。预览不会发送消息或调用模型。

| 页面 | 首先回答的问题 | 主要呈现 | 点击之后 |
| --- | --- | --- | --- |
| 总览 | 占多少，还能否继续，谁占得最多 | 当前 Token/窗口/百分比、下一步检查结果、最近输入、七类组成、逐次趋势、累计用量 | 类别进入内容列表；趋势定位具体请求；检查结果进入设置 |
| 内容查看器 | 哪一条内容占空间，来自哪里 | 类别、大小、来源、加入步骤、当前/已替换状态、内容预览 | 搜索、按大小或顺序排序；展开正文；压缩后可查看历史条目 |
| 变化记录 | 为什么增大或突然下降 | 每次请求输入/输出/缓存，增减图，压缩和注入事件 | 定位步骤、查看相关条目；展示替换片段的前后值和是否已应用 |
| 压缩设置 | 何时触发，整理到多少 | 触发比例、目标比例、提前量、输出/安全预留、模拟计算 | 保存后更新检查线；真实执行仍在完整请求组装后复查 |

前三项属于对话详情，压缩设置属于独立设置页。页面内增加数据密度，但使用 DSH 原生按钮、Input、Tag、SegmentedTabs、SettingsForm、Switch、字体和 `--dsw-*` 主题变量。仅组成图使用低饱和分类色，不改变宿主主题。

### 正式 UI 接入位置（本机源码已只读核验）

- `packages/client/ui-conversation/src/client/contract/slots.ts` 的 `conversation.view` 是会话作用域列表槽位。`ui-chat/src/client/apply.ts` 注册 `chat`、order 0；`ui-trajectory/src/client/index.ts` 注册 `trajectory`、order 10。本插件以独立 ID（建议 `context-manager`）、label“上下文”、order 20 注册。
- `ui-conversation/src/client/apply.ts` 从该槽位投影页签；`skeleton/ConversationSession.tsx` 的 `ConversationSessionHeader` 统一绘制同级标签；`DefaultConversationViews` 只渲染活动视图。无需改宿主头部、复制轨迹插件或用 DOM 插入按钮。
- `trajectory` 在宿主未启用开发者工具时可能隐藏；上下文页签独立注册，不随轨迹的可见性开关隐藏。两者都可见时，顺序为“对话 / 轨迹 / 上下文”。
- 读数和详情绑定实际挂载的会话作用域。切换会话后清空旧选中状态，取消旧详情读取，按 `sessionId + revision` 丢弃迟到响应；不能把上一会话的数据短暂显示在新会话里。
- `settings.section` 只挂压缩参数表单。对话中的设置链接只负责导航，不在数据视图再放一套可编辑参数。
- 头部会话标识、工作区选择、Bridge 菜单、`conversation.activity` 单一槽位、composer dock 和右侧面板均不在本次范围。以上是正式接入方案，当前独立预览没有注册真实宿主槽位。

## 数据口径与正式接入

| 数据 | 来源与计算 | 0.2.1 情况 | 正式增强要求 |
| --- | --- | --- | --- |
| 当前占用 | `contextPressure.projectedTokens`，最近输入锚点加后续内容变化估算 | 已有 | 标明估算、更新时间；换模型时标明容量与锚点可能不同步 |
| 最近请求输入 | `pressureTokens`，输入包含缓存读写，不含输出 | 已有 | 与当前占用分开显示 |
| 窗口、输出预留 | 窗口来自实际路由；预留来自请求配置及路由能力 | 窗口有；预留可能缺失 | 缺失时不猜测“可继续”；阈值展示仅为参考，实际由执行器检查 |
| 三类组成 | 官方 `contextBreakdown`：系统、工具定义、消息 | 已有 | 保持官方口径作校验，不把估算合计当成占用实测 |
| 七类组成 | 在当前有效 surface 中区分系统、工具定义、用户、注入、技能、助手、工具结果 | 未有 | 按官方估算器计价；技能依明确来源识别；无法分类保留未知项，不靠猜测强归类 |
| 系统指令 | 最后一个有效且非空的系统提示；可展示有来源证据的内部片段 | 未有正文索引 | 不把旧系统消息与生效系统提示重复计量；无法拆分时展示整条 |
| 工具定义与来源 | 当前请求 header 的工具 schema；注册来源元数据 | 仅 Top 8 大小 | 全量索引、分页与排序；协议开销单列或解释，不能强行等于逐条 schema 之和；来源未知显示未知 |
| 内容原文 | 选中 Session/seq/revision 后，通过宿主只读历史接口按需取正文 | 未有 | 打开条目再取；大结果分页；图片走宿主媒体引用；保持正文可复制、可读 |
| 逐次请求 | request/header、请求组装时点、assistant/message usage | 只有最近 12 次简表 | 同时保存请求索引、输入/输出/缓存回报和采样时点；缺 usage 不补 0 |
| 真实历史请求快照 | 请求当时 header 与有效 surface 的对应关系 | 未有 | 必须按位置重放替换，处理压缩移除、重复替换和系统头；不能直接按 seq 大小排序假装原请求 |
| 压缩事件 | start → summary/prune → 相邻 surface 替换 → end | 已有有界诊断 | 前后值只表示替换片段；目标与实测结果分开；失败、未应用、已替换后收尾失败、被中断分别呈现 |
| 累计用量与缓存率 | `tokenUsage` 的四个互斥桶；缓存读取 / 全部输入 | 已有 | 推理 Token 不重复计入；缓存仍占上下文；独立摘要调用不在宿主主请求累计范围中需标明 |
| 费用、跨会话关系、全局活动 | 需要独立计费与谱系来源 | 非当前核心职责 | 此阶段不复制用量统计和 Session Bridge 的业务；避免又一次越界改会话功能 |

每份读取结果带 `sessionId + revision + sampledAt + quality`。质量至少区分模型回报、估算、历史近似、未提供、过期；旧数据不能被新请求先到或后到的响应覆盖。

### 观察器结构

1. **轻量概览投影**：仅聚合计数、分组大小、最近请求信息、保留范围和修订号，不复制全文到会话列表。
2. **按需详情**：复用 DSH 官方 Session/Query/Connection 边界，按会话和游标返回请求、事件与内容索引。仅激活“上下文”视图时订阅；取消过期请求，切走后释放详情订阅，不持续轮询。
3. **按条正文读取**：根据已知 seq 与 revision 获取正文，不扫全盘、不重开 Agent、不发模型请求。先索引后正文，大记录分段；缓存可重建。
4. **独立压缩执行器**：现有策略仍是唯一配置来源；观察器只读，不决定实际放行。压缩事务复用宿主，失败时显示明确结果，不影响其他插件。

对 0.1.7-rc.2 做明确版本适配，不同时复制参考项目全部老版本兼容层。宿主当前 checkout 有其他任务的未提交改动，本轮没有写入宿主、Bridge 或日常 profile。

## 79.9% 示例的可核算结果

这是设计场景，不代表 DeepSeek 某个模型的真实窗口配置。

- 示例窗口 `128,000`；当前占用估算 `102,272`，即 `79.9%`。
- 保存触发 `80%`，提前量 `1%`，输出预留 `8,192`，安全空间 `2,560`。
- 实际检查线 `min(102,400, 117,248) - 1,280 = 101,120`，即 `79%`；当前超过 `1,152`，下一次请求先压缩。
- 组成估算之和 `95,360`，和当前占用是不同计量；七类占比以 `95,360` 为分母。
- 演示中替换旧片段 `39,140` → 摘要 `5,988`，净减少 `33,152`；当前占用随之变为 `69,120`，即 `54%`；组成估算变为 `62,208`。
- 被替换的 5 条进入历史状态，新增 1 条摘要；最新用户任务保留原文。历史条目不计入当前组成；勾选历史后列表合计明确写“含历史”。
- 改存 `85%`/`60%` 预设后检查线变为 `84%`，同一场景显示可继续；这由共用 `budget()` 得出。

## 预览的真实性边界

- **完整演示**：27 条设定内容、18 次设定请求、七类组成。正文是示意摘录，Token 是场景设定。压缩按钮只切换演示场景。
- **已有离线验收记录**：从既有隔离 profile 的 v3 测试夹具（日志格式 V4）checkpoint 导出数值；真实 AgentLoop 配模拟适配器，当前占用 `1,509/10,000`、三类组成 `16/27/177`、2 次请求、压缩片段 `7,908 → 120`。不是实际模型 API 用量，不是当前日常会话。
- **离线记录缺少的字段**：没有输出预留、逐次缓存值和全文索引，就显示未知或暂不支持；不补成七类详情。
- **历史请求联动**：预览提供“当前/保留条目中截至该步加入的相关内容”筛选，并明确不是完整历史请求重建。真正的按次组装快照在接入阶段实现并验证后才能改名。
- **压缩设置**：复用生产组件，保存仅写预览内存，刷新恢复默认。不会写用户配置。

## 下一阶段的明确验收标准

1. 固定一个当前会话修订，概览与官方占用读数一致；组成与实际有效 surface 对应，模型切换不混装时点。
2. 七类、技能来源、工具定义、图片、长输出、重复系统提示均能展开或明确说明缺失。
3. 第 N 次请求索引能正确关联 header/usage/surface；逆序端点、多次替换、压缩前历史与裁剪边界重放正确；不满足时标记历史近似。
4. 请求前压缩开始、成功替换、失败、中断均显示正确；当前任务与配对工具结果不丢失。用真实 AgentLoop 验证调用顺序，再做实际模型验收。
5. 大会话索引有界、详情分页、全文按需；切走上下文视图后无详情订阅与轮询残留；查看页面不触发 Agent/LLM。
6. 实际 Loader/profile 安装、只装本插件、卸载、与 Bridge 共存热更新均独立验证；原生同级视图切换、上下文详情、设置表单点击和真实模型验收单列，不能以静态预览代替。
7. “上下文”位于“轨迹”后，设置页只有参数；切换会话无串数据，切换视图不重置聊天；宿主原有统计、头部、Bridge 功能及样式保持各自独立。

本轮先交付呈现预览与数据接入方案。正式七类观察器、全文接口、历史重建还未写进安装包，不标记为已上线。
