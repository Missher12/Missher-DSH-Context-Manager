# 团队用量与压缩可追溯性实施方案

**目标：** 在现有会话用量与压缩面板中，增加真实团队汇总、摘要保留证据/连续变化对照，以及压缩前后可观察用量关联。

**方案：** 复用 `sessionQuery`、`attributeSession`、`estimateSessionCost`、摘要账本和现有内容来源索引；新增只读聚合与对照显示，不调用模型、不写会话数据、不创建团队。

**基线：** 本地工作树干净，位于 `c3f2fce`。本地 `origin/main` 引用领先一个仅新增项目 README 的提交 `3fbe647`；本轮不改 Git 状态。当前可用 Node 为监督提供的 `generation-zGhtjN` Node 24.22.1。

## 已有基础与数据口径

- Inspector 当前只读取所选会话；已有请求归因会按失败/取消结算与 `llm/retry-started` 重试边界处理用量，未知分量不补零。费用只对已支持的 DeepSeek 路由估价；自定义或未定价模型仍显示 Token、费用未知。
- `agentTeam` 投影总会包含 lead 行，不能以投影存在或 `parentSession` 单独判为团队。以 lead 日志中的持久 `team/member` roster 为成员证据，再用 `traceSession` 校验关系；必须至少有一名 roster teammate。成员 ID 按不透明字符串匹配，不要求 `session-` 前缀。只把与该 roster 和 lineage 同时吻合的后代纳入，并按 session ID 去重；普通 fork 不计入。已结束但有可读持久记录的 roster 成员保留。无法读取或无法证明时显示未知/不纳入，不以 0 代替。
- 团队成员的 `tokenUsage` 投影不能直接相加：session projection 会折叠继承事件，而该投影初始化不扣除 `inheritedEventCount`。团队用量对每个成员只折叠 `events.slice(inheritedEventCount)`，复用 `attributeSession` 的结算和重试口径；成员上下文各自显示，不拼成一个窗口。摘要/修复用量仅在摘要账本尝试与 `compactionId` 可对应时归属该次压缩；用途只有在 `SummaryOperations` 的 attempt 关联可证时才拆分。
- 已有七字段摘要结构校验、摘要来源分页、原文跳转、压缩前后替换片段 Token、摘要/修复账本、实际请求缓存明细，以及 waiting/skipped/failed 等闲置/压缩状态。结构有效不代表语义完整。

## 最小实施范围

1. **团队切换与汇总**（`src/inspector.ts`、`src/inspector-types.ts`、`src/inspector-wire.ts`、`src/client.tsx`、`src/inspector-charts.tsx`、必要样式/文案）：增加“本会话 / 包含团队”切换。主行显示各成员 Token 占比条、名称、最近可证模型、请求/重试、缓存与摘要用量；展开时按需读取该成员现有上下文与摘要来源视图。成员日志用 `projectionMode: none` 做自有事件归因，lead roster 单独读取并验证；不激活 Agent。无真实 teammate 时不出现团队总计。
2. **摘要保留证据与相邻摘要对照**（新增小型纯逻辑 helper，接入 `src/context-overview.tsx` 与现有 `content()` 来源读取）：在可解析摘要详情中，将原文可追溯的路径、编号/版本/日期及明确约束/待办锚点与七字段摘要做保守的文本证据核对。显示“找到对应文本 / 需人工核对”及原文入口；不计算质量分或完整率。相邻、可解析摘要按字段比较：精确匹配标为保留，新增/未再出现按文本差异列出，改写只标“文本有变化”，不推断语义等价；每项保留来源链接。无来源、旧格式或历史不全时明确显示不可完整比较。
3. **压缩效果与运行状态关联**（复用 `src/inspector-charts.tsx` 和现有 readout）：在已有压缩记录详情中并列显示被替换片段前后 Token、可精确关联的摘要/修复尝试，以及压缩后至下一次压缩前实际请求的输入/缓存/输出记录。费用只引用已发生且可定价的请求；上下文释放量不折算成现金节省。等待、跳过、失败原因复用现有 `idleStatus`、压缩记录与 reason/message，在现有状态/记录位置显示，不另建状态机。

## 验收与边界

- 用合成数据覆盖：空 roster/普通 fork 排除、真实 roster 成员（含非 `session-` ID 和已结束记录）、可证后代去重、继承事件不重复、重试仍计费、缺失用量/价格保持未知；摘要锚点命中与需人工核对、相邻摘要新增/保留/文本变化、旧格式/缺来源降级；容量变化不生成反事实现金节省；等待/跳过/失败沿用现有状态。
- 只用监督提供的既有只读团队样本和合成数据验收；不改样本、不启动 Agent/团队、不发起模型请求、不停止 DSH 会话。变更后只跑相关测试、类型检查与构建。完成候选包后先交监督审查；安装须等宿主安全空闲并由监督会话做原生界面验收，沿用原插件实例与现有安装接口。
- 不改 80% 触发、空闲 15 分钟、既有会话数据或后台行为；本任务不指定版本、不提交/推送/发布、不新增 Actions。

## 本轮复核口径

- 先核实目标自己的持久 roster；只有 lead ID 与目标一致且至少有一名 teammate 时才采用。否则只接受直接父会话的有效 roster 明确把目标列为 teammate，并结合 lineage 验证。lead-only roster 可证明“不是团队”；roster 缺失、畸形或无法读取时显示“无法核实”。普通 fork 不计入团队总量。成员用量归因使用 `projectionMode: none` 和自有事件区间；roster 检查、团队 lead 读取与成员用量读取分别保留观察租约。
- 摘要账本的合计仅覆盖 `since` 之后且仍可归属的尝试；压缩早于该时间、尝试已归档/未保留或 `compactionId` 无映射时标为部分或未知。若成员压缩期间请求可能与账本重复，保留请求/摘要分项，但该成员不进入团队 Token 合计。
- 相邻摘要用精确文本差异，不做语义判断。来源核对由目标、当前摘要 ID 和前一摘要 ID 固定一次读取截面；新事件到达不重扫同一组摘要。输入里无法证明下一次压缩起点的旧记录只显示范围未知，不显示 0 Token。
- roster 的 `active/provisioning/failed` 只呈现为“已就绪/创建中/创建失败”，不推断任务正在运行或已结束。团队行为与窄屏、长名称、展开详情使用离线合成数据和真实组件检查；已归档的原生团队样本暂不可从宿主打开，本轮不更改归档状态，也不安装候选包。原生验收仍由监督在可打开的会话完成。

**待实施时确认的技术边界：** roster 投影缺失或报错、成员日志不可读、汇总超过现有分析上限时必须给出未知/受限结果，不扩大为全面扫描。摘要锚点只是可核对的字面证据，可能漏掉语义改写；历史摘要账本对过旧尝试只保留总计，无法伪造单次压缩归属。
